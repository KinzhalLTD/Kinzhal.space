# كينجال نست (Kinzhal Nest) على Netlify وFirebase · دليل الإعداد

موقع خاص لإدارة ألعابك، ويشمل:
- تسجيل دخول بالبريد وكلمة المرور.
- فريق بأدوار: مالك ومحرر ومشاهد.
- مساحة عمل مشتركة.
- مزامنة ليلية لأرقام Firebase وAdMob وApp Store Connect وRevenueCat وCrashlytics.

التفاصيل الكاملة بالإنجليزية في README.md.

## الحماية
- **كلمات المرور:**
  - تديرها Firebase Authentication فقط، ولا يراها كينجال نست ولا يحفظها.
  - تُشترط ١٢ حرفاً مع حروف كبيرة وصغيرة ورقم ورمز.
  - تُرفض الكلمات الشائعة والتكرار واسم بريدك.
  - تُفحص مقابل التسريبات المعروفة دون إرسال كلمة المرور نفسها.
- **قبل الدخول:** تأكيد البريد إلزامي، والدخول بالدعوة فقط.
- **التحقق بخطوتين:** عبر تطبيق مصادقة، ويستطيع المالك فرضه على الجميع.
- **منع التخمين:** إيقاف مؤقت بعد المحاولات الفاشلة.
- **إنهاء الجلسات:**
  - خروج تلقائي بعد ٣٠ دقيقة من عدم النشاط.
  - زر «الخروج من كل الأجهزة».
  - حذف النسخة المحلية من البيانات عند الخروج.
- **مفاتيح API:** مشفّرة بـ AES-256 في Firestore، ولا يستطيع المتصفح قراءتها إطلاقاً.
- **المتصفح:** ترويسات أمان صارمة (CSP وHSTS ومنع التضمين).

## ١. مشروع Firebase
1. من console.firebase.google.com أنشئ مشروعاً، أو استخدم مشروع ألعابك.
2. **Authentication ← Sign-in method ← Email/Password ← Enable**.
3. **Authentication ← Settings:**
   - **Password policy:** فعّل الإلزام، ١٢ حرفاً كحد أدنى، وحروف كبيرة وصغيرة وأرقام ورموز.
   - أبقِ **Email enumeration protection** مفعّلاً.
   - أضف نطاق موقعك في **Authorized domains**.
4. **Firestore Database ← Create database** بوضع Production.
5. **Firestore ← Rules:** الصق محتوى ملف `firestore.rules` ثم **Publish**.
6. **Project settings ← Your apps ← Web app:** سجّل تطبيقاً وانسخ `apiKey` و`appId`.
7. **Project settings ← Service accounts ← Generate new private key** واحفظ الملف بسرية.

**اختياري (موصى به): التحقق بخطوتين.** رقِّ المشروع إلى Identity Platform (مجاني)، ثم فعّل TOTP بالأمر الموجود في README.md.

## ٢. موقع Netlify
1. ارفع محتوى المجلد إلى مستودع **GitHub خاص**، ثم في Netlify اختر **Add new site ← Import an existing project ← GitHub**. لا يوجد أمر بناء، ومجلد النشر هو `public`.
   - لا تستخدم السحب والإفلات (Netlify Drop) لأنه ينشر الملفات الثابتة فقط دون دوال الدخول والمزامنة.
   - الخطوات مفصّلة أيضاً داخل المنصة: الأكاديمية ← النشر والاستضافة.
2. **Site configuration ← Environment variables:** أضف المتغيرات التالية:
   - `FIREBASE_PROJECT_ID` و`FIREBASE_CLIENT_EMAIL` و`FIREBASE_PRIVATE_KEY`: من ملف حساب الخدمة.
   - `FIREBASE_WEB_API_KEY` و`FIREBASE_APP_ID`: من الخطوة ١-٦.
   - `APP_SECRET`: ٤٨ حرفاً عشوائياً أو أكثر. **لا تغيّره لاحقاً**، فالمفاتيح المحفوظة مشفّرة به.
   - `OWNER_EMAIL`: بريدك، ويصبح هذا الحساب المالك.
   - `SITE_URL` (اختياري): عنوان نطاقك الخاص.
3. **Deploys ← Trigger deploy**.

## ٣. أول دخول
1. افتح الموقع واختر **مدعو؟ أنشئ حسابك** ببريد المالك.
2. أكّد البريد من الرسالة ثم اضغط **أكدته**.
3. من **الحساب والفريق**:
   - فعّل التحقق بخطوتين.
   - ادعُ فريقك.
   - اختيارياً: افرض التحقق بخطوتين على الجميع.

## ٤. الاتصالات (التقارير ← البيانات)
الدليل الكامل خطوة بخطوة مع حلول الأخطاء الشائعة موجود داخل المنصة في **الأكاديمية ← ربط واجهات API**.

1. **Google:** اتبع الخطوات الأربع في البطاقة:
   - فعّل الواجهات.
   - انشر شاشة الموافقة.
   - أنشئ OAuth client من نوع Web وأضف رابط الرجوع الظاهر.
   - الصق المعرّف والسر ثم اضغط **تسجيل الدخول عبر Google**.
2. **App Store Connect:**
   - اختر ملف ‎.p8 ويُقرأ معرّف المفتاح من اسمه.
   - أضف Issuer ID ورقم المورد ثم **احفظ واختبر**.
3. **RevenueCat:** الصق مفتاحاً سرياً V2 ثم **احفظ واختبر**.
4. اضغط **اكتشف ألعابي** وراجع النتائج ثم **تطبيق المحدد**.
5. **مزامنة الآن:** اختر «آخر ٩٠ يوماً» أول مرة، وبعدها تعمل تلقائياً كل ليلة الساعة ٦ صباحاً بتوقيت الرياض.

## الأدوار
- **المالك:**
  - كل الصلاحيات.
  - وحده يغيّر المفاتيح والفريق.
- **المحرر:**
  - يغيّر الخطط والمهام والتكاليف ومعرّفات الألعاب.
  - يشغّل المزامنة والاكتشاف.
- **المشاهد:** يطّلع فقط.
